# MONEY Ω validation ladder · 2026-10-25 · 0.1

1. Observe and hash public data with source identity, timestamp scope and unit.
2. Validate exact contracts, windows, resolution and costs. No proxy Pspot→Pcontract.
3. Attribute typed judgments to their model version and question; test drift,
   malformed output, staleness, missing data and adverse scenarios.
4. Register prospective hypotheses before outcomes. Do not backdate judgment,
   reconstruct opening captures or treat a source hash as producer identity.
5. Reconcile outcomes to the same contract/source and record uncertainty, costs,
   sample dependence, calibration and baselines. No fill is assumed here.
6. Evaluate net performance under paper assumptions and red-team failure modes.
7. Only a separately implemented account/risk/authorization/execution runtime can
   later evaluate LIVE operation. No completion of this ladder grants permission.
